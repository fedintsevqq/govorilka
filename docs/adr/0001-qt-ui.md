# 0001. Интерфейс на Qt (PySide6 + QML) вместо Tkinter

Дата: 2026-10-23. Статус: принято.

## Контекст

Нужны значок в строке меню macOS и в трее Windows, круговое меню по горячей клавише с плавной
анимацией и полупрозрачностью, сворачивание в трей. Tkinter не умеет ни значков в трее и строке меню,
ни полупрозрачных окон с попиксельной прозрачностью и аппаратной анимацией.

## Варианты

1. **Qt (PySide6 + QML).** Всё остаётся на Python, один процесс. `QSystemTrayIcon` даёт трей Windows
   и значок строки меню Mac. QML рисует на видеокарте и анимирует плавно.
2. **Tauri + React/TypeScript.** Лучшие возможности для внешнего вида, но второй язык, Rust в сборке
   и обмен с ядром на Python через отдельный процесс.

## Решение

Qt (PySide6-Essentials 6.11.2). Версия 6.11 выбрана потому, что 6.12 на macOS требует 14+, а мы
поддерживаем Intel-Mac с macOS 13.

## Как устроено

- `govorilka/controller.py` — логика приложения без интерфейса: запись, пауза, отметки, файлы,
  горячая клавиша, Claude Code. Сообщает о событиях через обратные вызовы из любых потоков.
- `govorilka/qt/` — мост к QML (`Backend`, модель транскрипта), трей, запуск.
- `govorilka/qml/` — окна: главное, настройки, круговое меню, плашка записи.
- Ядро (запись, распознавание, голоса, эхоподавление) не меняется и тестируется без интерфейса.

## Последствия

- Сборки вырастают примерно на 60–90 МБ (Qt).
- Интерфейс можно проверять без экрана (`QT_QPA_PLATFORM=offscreen`) в тестах и в CI.
- Настоящего размытия фона под окном Qt не даёт; используем тёмную полупрозрачную «плиту» с тенью.
